# AWS SAM for infrastructure as code

The AWS side of ADR 0001 is defined with AWS SAM in `infra/template.yaml`, plus a one-time `infra/bootstrap.yaml` for the GitHub deploy role and image repository. SAM is CloudFormation with short forms for Lambda, SQS triggers, schedules and function URLs, so the whole stack fits in one file, AWS keeps the state, and `sam build`/`sam deploy` build and push the Lambda image without extra scripts. Terraform appears in more job posts but needs a state bucket and lock set up first and a separate image push step; AWS CDK (Python) would keep infrastructure in the API's language but needs `cdk bootstrap` and Node for its CLI. Both are more moving parts than four functions, a queue and a bucket need. Vercel and Neon stay outside the template; `scripts/setup-aws-deploy.sh` walks through them. We would revisit this if the infrastructure spreads beyond AWS or grows past what one template keeps readable.
