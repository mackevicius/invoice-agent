# Domain docs

Layout: single-context. Domain terms live in root `CONTEXT.md`; decisions live in `docs/adr/`.

## Before exploring

Read root `CONTEXT.md` and relevant ADRs in `docs/adr/`.
If `CONTEXT-MAP.md` exists, follow it to relevant contexts and their ADRs instead.
If docs are missing, proceed silently without suggesting or creating them upfront. `/domain-modeling` creates them as terms or decisions are resolved.

## Vocabulary and decisions

Use glossary terms in issues, proposals, hypotheses, and tests. Note genuine gaps for `/domain-modeling`.
If a proposal conflicts with an ADR, name the ADR and explain the conflict explicitly.
